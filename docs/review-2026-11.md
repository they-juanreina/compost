# compost — status, overlap & market review (2026-11-11)

A point-in-time review: where compost stands, what Claude Code / Desktop / Cowork
now does natively (so compost shouldn't), what the market ships, and which gaps
are worth closing. Every gap below was run through the `CLAUDE.md` pre-flight
(kill filter → not-the-analyst → human-stays-free → validated need).

## 1. Status

- **Version:** v0.2.1 tagged; memos (milestone #9), `.vtt`/`.srt` import and the
  Node 26 fix sit under CHANGELOG *Unreleased* — no release cut. Plugin manifest
  and `plugin/package.json` still say `0.1.2`.
- **Health:** `pnpm install --frozen-lockfile`, `pnpm build`, `pnpm test` all
  green on Node 26 — 860 tests (cli 645, web 51, retrieval 65, provenance 51,
  plugin 30, evals 18), 0 failures.
- **Surface:** 38 CLI verbs (3 stubs: `serve`, `query`, `synthesize`), 23 MCP
  tools, 9 skills, 8 slash commands. Web is a typecheck-only shell.
- **Cadence:** 282 commits in June 2026, 5 in July, then one hotfix (2026-10-14).
  Dormant since early July.
- **Open work:** 19 issues, none touched since 2026-07-04. 16 are the v0.3 web
  milestone (gated by the #310 "needs design" decision); #325, #317, #159 are
  unmilestoned. Open PRs: #329 (dependabot, Aug), #326 (draft docs, Jul).
- **Doc drift fixed in this pass:** README verb list (was missing 11 verbs) and
  MCP tool count (21 → 23); `plugin/README.md` rewritten (listed 4 of 8 commands,
  4 of 9 skills).
- **Dangling stubs:** `query` → #51, `synthesize` → #59, `serve` → #32 — all three
  issues are **closed**, so the stubs point nowhere.

## 2. Overlap with Claude Code / Desktop / Cowork

| compost capability | Claude native? | Verdict |
|---|---|---|
| Plugin packaging, slash commands, skills, subagents | Yes | Leverage — already does |
| Autonomous loops / scheduling | Yes (desktop scheduled tasks, cloud routines, Cowork `/schedule`) | Don't build a scheduler; keep `watch` as the human/offline path |
| Reading PDF/DOCX/PPTX/XLSX/CSV | Mostly (ad hoc, size-capped, no seed structure) | Keep only normalization into the seed shape |
| Projects knowledge / RAG, memory | Partial (opaque, no hybrid control, no citation validation) | compost's inspectable hybrid index + validated citations stay unique |
| Interactive UI | Partial — artifacts with persistent storage, connectors; **text-only storage** | Artifacts can replace most of the planned Next.js app; audio/video playback can't |
| Local audio transcription, diarization, typed silences, cues, frames | No (voice dictation is live-only, cloud-processed) | **Unique** |
| Local embeddings + LanceDB hybrid BM25+dense RRF | No | **Unique** |
| Typed qual model (highlight → code → category → theme, lenses, memos) | No (conversational only) | **Unique** |
| Saturation, κ/α agreement as reproducible computation | No (an agent can compute ad hoc, not durably) | **Unique** |
| Three-actor append-only provenance, `blame`, PROV-O, `[draft]`→`endorse` | No audit trail of AI vs human edits found | **Unique — the moat** |

Overlap is growing fastest in orchestration and UI (plugins, hooks, scheduling,
artifacts). The defensible core is the data + trust layer. Re-check quarterly.

## 3. Market

- **MCP is now table-stakes, not a differentiator.** Dovetail (read-write MCP,
  May 2026), Great Question (write GA, Apr 2026), Marvin, Condens (read-only),
  Looppanel (beta), Granola, Otter all ship MCP/connectors.
- **Nearest threat: ATLAS.ti v26.1 (Jun 2026) ships a *local* MCP server** in
  every Desktop subscription — an AI client reads and writes codes, memos,
  quotations locally. That is compost's "agent drives the QDA tool" pitch, from
  an incumbent with a GUI. No evidence it marks or gates AI-authored output.
- **NVivo AI Cloud** (Sep 2026) moves the other big CAQDAS tool to cloud AI.
- **Closest open-source peers:** anarlog (local capture, MCP — the call, not the
  corpus), QualCoder/Taguette (local, no AI), loose qual-coding skills and a
  QualAI MCP server. None combine local transcription + retrieval + provenance +
  agreement stats.

**Where compost is ahead:** cue-rich transcripts; AI-vs-human provenance with an
endorsement gate; saturation + agreement driven by an agent; fully local + MIT.
**Where it's behind (table-stakes):** team sharing; a GUI for non-agent users;
stakeholder outputs (reports, clips/reels); REFI-QDA `.qdpx` interchange;
importers (Dovetail, other tools).

## 4. Gap decisions

### Closed in this pass
- **#325 ingest-provenance event** — ADR 0006 accepted it and it passes the
  pre-flight (durable local provenance no agent can supply); it closes a §13
  silent write on every landing — `import`, direct `transcribe`, and both queue
  workers. 877 tests pass (+17), lint clean.
- **Doc drift** (README, plugin README).

### Killed (fail the pre-flight)
- **`compost synthesize`** — autonomous theme synthesis is interpretation (fails
  #2) and the host agent already does it via the `thematic-coding` skill. Remove
  the stub.
- **`compost query`** — one-shot RAG duplicates `search` + `chat` (fails #1 and
  §7 "name it once"). Remove the stub.
- **A compost scheduler / autonomous-loop runner** — Claude scheduled tasks and
  routines cover it (fails #1). `watch --once` under the user's own cron/launchd
  stays the human-free path.
- **Rebuilding Claude's document readers** — keep normalization only.

### Re-scope (decided 2026-11-11 — #310)
- **v0.3 web UI (16 issues)** — worked through in
  [ADR 0007](adr/0007-visual-surface-rescope.md) (Accepted). In short:
  - #119–#122 are already built in `web/lib` and only need closing.
  - A **review artifact** (read + endorse/reject over compost's local MCP server)
    replaces the seed home, lineage, codebook and comparison pages.
  - `compost serve` shrinks to a **local player** with select-to-highlight — the
    one thing an artifact can't do, and the only visual surface that works
    offline without a Claude account.
  - The chat panel is killed. The theme board is kept (maintainer override) but
    in the local player, with auto-layout: an artifact board would record a
    researcher's drags as AI-authored, because the MCP create tools always
    stamp `--ai`.
  - Two CLI gaps surfaced and block any review surface: there is **no
    `compost reject` verb** (docs say there is) and **no query that lists
    highlights, codes or themes** (`status` gives counts only).

### Proposed (pass 1–3, need validation — rule #4)
1. **REFI-QDA `.qdpx` export (then import).** `export` is a compost capability
   over local state, and it's the migration path to/from ATLAS.ti, MAXQDA,
   NVivo. Dovetail import was asked for in the 2026-07-01 dogfood session.
   Validate with one real round-trip into ATLAS.ti or MAXQDA before building.
2. **Marketplace-installable plugin.** The committed `plugin/dist` needs the
   workspace `node_modules` and a built CLI, so it can't install from a plugin
   marketplace. Bundle the MCP server and add `.claude-plugin/marketplace.json`.
   Install and setup opacity came up in the 2026-07-01 dogfood session.
3. **Team sharing as `export`, not as a server.** The 2026-10-14 phased plan
   (static drop → git auto-sync → pipeline) fits compost's local-first stance:
   phase 1 is an `export` bundle of endorsed evidence (themes + codes + quotes +
   lineage) for a shared folder. No multi-user server.
4. **Stakeholder readouts** stay with skills + artifacts/Office skills (the
   analyst's job), fed by endorsed-only queries — no compost report engine.

### Positioning update
Lead with what ATLAS.ti's MCP and Dovetail's MCP don't show: **AI output is
`[draft]` until a researcher endorses it, and every claim traces back to an
utterance with `blame`.** "Agent can drive it" is no longer the pitch.
